# Recap Bot

Telegram-бот делает короткий живой пересказ русскоязычного группового чата. Он хранит сообщения последних 24 часов в памяти, умеет начинать рекап с сообщения, на которое ответили командой `/recap`, расшифровывает голосовые сообщения и кружочки, а затем обращается к OpenAI-совместимому API.

При наличии PostgreSQL с расширением pgvector администратор может включить для конкретного чата постоянное хранение и индексацию командой `/search_on`. После этого бот поддерживает полнотекстовый поиск обсуждений командами `/search`, `/s`, `/п` и префиксом `?`. По умолчанию хранение, индексация и поиск во всех чатах выключены.

## Возможности

- `/recap` — пересказ доступной переписки за последние сутки.
- `/recap` ответом на сообщение — пересказ начиная с этого сообщения.
- `/privaterecap` — то же, что `/recap` (в том числе ответом на сообщение), но рекап приходит в личные сообщения, а сама команда удаляется из чата. Чтобы бот мог написать в личку, откройте с ним диалог и нажмите `/start`; иначе бот упомянет вас в чате с подсказкой. Для удаления команды боту нужно право администратора «Удаление сообщений» — без него рекап всё равно придёт в личку.
- `/start` — то же, что `/help` (нужен, чтобы открыть диалог с ботом для `/privaterecap`).
- `/help` — краткая инструкция.
- `/search_on` — включить хранение, индексацию и поиск в текущем чате (только администраторы чата).
- `/search_off` — выключить хранение, индексацию и поиск в текущем чате (только администраторы чата).
- `/search <запрос>`, `/s <запрос>`, `/п <запрос>` или `? <запрос>` — поиск обсуждений в истории текущего чата (только при PostgreSQL). Под результатом кнопки «◀️ Назад», «👌 OK» и «Ещё ▶️».
- `/init` — загрузить экспорт Telegram Desktop (`result.json`, `.json.gz` или `.zip`) для импорта истории (только администраторы чата).
- `/init_status` — показать количество сообщений и фрагментов в базе данных.
- `/init_cancel` — отменить текущий импорт.
- Расшифровка голосовых сообщений и видеокружков.
- Описание изображений: одиночное фото — через BIG-модель, альбом (до 3 фото) — через SIMPLE-модель.
- Безопасная проверка созданных моделью ссылок на сообщения.

История для `/recap` хранится в оперативной памяти (последние 24 часа). Постоянное хранение в PostgreSQL включается отдельно для каждого чата командой `/search_on`. Для чтения обычных сообщений в группах отключите privacy mode через BotFather, а затем заново добавьте бота в группу.

## Установка и запуск

Требуется Python 3.10 или новее.

```bash
cd recap
python -m venv .venv
source .venv/Scripts/activate
pip install -r requirements.txt
```

### Только память (без PostgreSQL)

Задайте обязательные переменные окружения:

```
TELEGRAM_BOT_TOKEN=...
OPENAI_TOKEN=...
```

```bash
python recap/recap.py
```

### С PostgreSQL и pgvector

Установите PostgreSQL 14+ и расширение pgvector:

```bash
# Ubuntu / Debian
sudo apt install postgresql postgresql-contrib
sudo -u postgres psql -c "CREATE EXTENSION vector;"

# macOS (Homebrew)
brew install pgvector
```

Создайте базу данных и пользователя:

```sql
CREATE USER recap_user WITH PASSWORD 'secret';
CREATE DATABASE recap OWNER recap_user;
\c recap
CREATE EXTENSION IF NOT EXISTS vector;
```

Задайте переменные окружения (таблицы создаются автоматически при первом запуске):

```
PG_DATABASE=recap
PG_USERNAME=recap_user
PG_PASSWORD=secret
PG_HOST=localhost
PG_PORT=5432
```

## Поиск обсуждений (/search, /s, /п, ?)

По умолчанию поиск и постоянное хранение выключены. Администратор или владелец чата включает их командой `/search_on` и выключает командой `/search_off`. В личном чате эти команды доступны его пользователю. Выключение прекращает сохранение новых сообщений и фоновую индексацию, но не удаляет уже сохранённую историю; после повторного включения обработка продолжится.

Цель поиска — найти место, где тему **обсуждали**, а не сообщение, где про неё только спросили. При наличии PostgreSQL и включённой индексации бот:

1. Нормализует запрос через LLM: извлекает ключевые слова (с синонимами), фильтры по дате, участникам и точным фразам. Если LLM недоступна, ключевые слова берутся из запроса без служебных и вопросительных слов.
2. Выполняет полнотекстовый поиск по отдельным сообщениям (`messages.tsv`, словарь `russian`, GIN-индекс). Ключевые слова объединяются через ИЛИ и ищутся по префиксу, поэтому сообщению не нужно содержать все слова вопроса. Команды бота, поисковые запросы (`/…`, `? …`) и сообщения самого бота в выдачу не попадают.
3. Группирует найденные сообщения в обсуждения (сообщения с разрывом не больше 45 минут). Обсуждение ранжируется по релевантности, покрытию ключевых слов и числу участников; одиночный вопрос («а кто знает про X?») получает штраф, упомянутый в запросе участник — бонус.
4. Если обсуждений найдено мало, добавляет семантически близкие фрагменты из векторного индекса (pgvector), не пересекающиеся с уже найденными.
5. Проверка релевантности: для каждого найденного обсуждения загружается окно переписки вокруг него, и один запрос к LLM оценивает все кандидаты сразу. Отбрасываются те, где совпало лишь слово, тему упомянули вскользь или только задали вопрос без ответа; оставшиеся (не больше 5) упорядочиваются по полезности.
6. Для каждого оставшегося обсуждения LLM формирует короткий ответ со ссылками, ниже — выдержка из 3–4 ключевых сообщений со ссылками. Если LLM отвечает, что ответа в переписке нет, такой результат не показывается. Если не осталось ни одного результата, бот честно пишет «Не нашёл…» и предлагает переформулировать запрос. Все страницы готовятся сразу, поэтому листание мгновенное, а счётчик «k/N» точный.
7. Под результатом кнопки:
   - «◀️ Назад» — предыдущий результат (нет на первой странице);
   - «👌 OK» — убирает кнопки, результат остаётся;
   - «Ещё ▶️» — следующий результат (нет на последней странице).

   Кнопки меняют текст этого же сообщения. Нажимать кнопки может только тот, кто запустил поиск. Состояние поиска хранится в памяти 24 часа; после перезапуска бота кнопки сообщают, что поиск устарел.

Все ссылки на сообщения строятся приложением (не LLM) и проверяются перед отправкой.

Сообщения с отрицательными id — это история чата до преобразования обычной группы в супергруппу (так их выгружает Telegram Desktop). Они участвуют в поиске и попадают в выдержку, но ссылок на них нет: в супергруппе такие сообщения не открыть.

### Миграция базы

Схема обновляется автоматически при запуске бота: в таблицу `messages` добавляется генерируемая колонка `tsv` и GIN-индекс `messages_tsv` (`ADD COLUMN IF NOT EXISTS` / `CREATE INDEX IF NOT EXISTS`). PostgreSQL сам заполняет колонку для уже сохранённых сообщений, повторная индексация или импорт не нужны. На большой таблице первый запуск после обновления может занять немного больше времени: таблица перезаписывается один раз.

⚠️ Стабильные ссылки на сообщения (`t.me/c/...` или `t.me/<username>/...`) существуют в Telegram только для супергрупп/каналов. В обычной (не супер) группе без публичного username ссылку построить невозможно — в этом случае вместо `<a href>` в ответе показывается обычный текстовый маркер `(#N)`, а связь с источником обеспечивается только через реплай.

## Импорт истории (/init)

Позволяет загрузить экспорт Telegram Desktop для заполнения исторической базы данных. Команды импорта доступны только после `/search_on`.

1. Только администратор или владелец чата может запустить `/init`.
2. Бот ожидает файл: `result.json`, `result.json.gz` или ZIP-архив с экспортом.
3. Файл разбирается потоком через `ijson` и нормализуется.
4. ⚠️ После успешного разбора файла вся ранее сохранённая история этого чата (сообщения и фрагменты) удаляется, и импортированные сообщения загружаются в базу данных с нуля — это гарантирует полную переиндексацию без смешивания со старыми/частичными данными.
5. Прогресс показывается редактированием статусного сообщения.
6. `/init_cancel` останавливает импорт; уже загруженные записи сохраняются, история не восстанавливается.
7. После импорта фоновый индексатор автоматически обработает новые сообщения (индексация идёт непрерывно, пока есть очередь).

## Тесты

```bash
pytest recap/
```

Тесты не обращаются к сети, Telegram или LLM API.

- Unit-тесты проверяют чистые функции и обработчики с заглушками.
- E2E-тесты (`test_e2e_*`) пропускают настоящие JSON-апдейты через собранное приложение (`build_application`): работают реальные фильтры и маршрутизация хендлеров, сериализация Bot API. Telegram заменён фейковым сервером внутри процесса (`FakeTelegram`), который записывает все вызовы Bot API, LLM — фейковым клиентом. Покрыты `/recap`, `/privaterecap` (личка, удаление команды, закрытая личка, нет прав на удаление) и поиск с кнопками «OK»/«Ещё».
- E2E-тесты поиска и миграции работают с настоящим PostgreSQL + pgvector, который пакет `pgserver` запускает локально во временной папке. Тесты выполняют реальный SQL и проверяют миграцию схемы на базе в «продовом» состоянии со старыми данными. Если `pgserver` не установлен, эти тесты пропускаются.
